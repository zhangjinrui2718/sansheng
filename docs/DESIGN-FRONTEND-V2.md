# 三生前端 V2 · 重做设计书

> **地位**:意图与判据,不是编年体日志。取代 `DESIGN-FRONTEND-UX.md` 与
> `DESIGN-FRONTEND-IA.md` 作为现行前端设计依据(那两份封存为历史,不再追加)。
> 事实底稿仍是 `DOMAIN-MODEL.md`(端点/闭集/动线),本文与它冲突时**以事实底稿为准**。
> **起因**:用户对 v3→v5 重构不满,裁决四词目标 —— **低耦合、高内聚、简约、科技办公**;
> 设计体系参照 Multica(`docs/theming.md` 为其规格书)。
> **范围**:后端契约冻结不动(62 路由 + WS 事件面 + 读面);前端换骨架迁内脏。

---

## 1. 不变的魂(重做不许碰的东西)

这些是 Sansheng 的产品本质,任何视觉/结构重做都不改动它们:

1. **后端零改动**:所有端点、读面、WS 契约照旧消费。
2. **领域正典链**:项目 → 会话线(main/thread)→ 消息;工作项(树+依赖)→ 工件
   (正文在仓)→ 双裁决(质检 pass/fail + 甲方 accept/reject)→ 交付线 → 收口 → 版本链。
3. **四个「等甲方」状态点**是动线的心脏:① 确认开工 ② 答问 ③ 验收 ④ 收口同意。
4. **对话是主轴**:甲方只与业务经理对话;其余角色由排空器驱动,甲方是观察者。
5. **验证过的行为判据全量保留**:WS 事件只递增 revision、页面回查 REST;「读不到 ≠ 没事」
   四态;interrupt 只停甲方通道;断线如实说;乐观上屏撤回;实体脊四纪律
   (标签契约/邻居有地址/拿不到就明说/真 `<a>`);深链 `?project=` 坐标三纪律。
6. **v5 中正确的裁决保留**:成员全员并发板;工作项三视图一画布;对话面去角色化;
   表态完结后在流里塌缩成一行事实;已收口项目灰阶。
7. **测试文化**:哨兵钉判据 + 变异自检;不追测试总数,追「每条判据仍被钉住」。

## 2. 动线(甲方的八步,IA 按它组织)

```
接待(零项目自动进) → 对话立项 → ①确认开工 → 执行期观察(对话/项目/工作项/成员)
  → ②答问 → 汇报合并窗口(攒3条或5分钟) → ③验收(拒→返工→再交) → ④同意收口
  → 收口后可对话 / 开新版本
```

四状态点的判据与端点见事实底稿 §4;每一步都落在「对话页」或「从对话页一跳可达」。

## 3. 信息架构

### 3.1 布局:恒定三区(工作台形态)

```
┌───────────────────────────────────────────────────────────┐
│ 顶栏:状态·模型·用量 ····························· 设置 ⊙    │  ← frame 底色
│ ┌────────┬──────────────────────────────────────────┐     │
│ │ 左栏    │   页面卡(圆角 page-canvas,浮在 frame 上)      │     │
│ │ 导航×5  │   ┌────────────────────┐ ┌────────────┐ │     │
│ │ ────── │   │      页面内容        │ │ 实体详情抽屉 │ │     │
│ │ 项目列表 │   │                    │ │ (全局,按需) │ │     │
│ └────────┴──────────────────────────────────────────┘     │
└───────────────────────────────────────────────────────────┘
```

- **页面即卡片**(Multica 布局语言):内容区是圆角页卡,带发丝边,浮在 frame 上;
  frame 与页卡两层底色拉开层级。这是「科技办公」质感的最大来源。
- **左栏全路由恒在、可折叠**(v5 只在对话页出现 → 修「项目仪表盘藏二级链接」的断裂);
  项目列表按状态分组:在等你 → 在跑 → 停着 → 进行中 → 已收口(空组不渲染);
  在跑项目带呼吸脉搏点(全站唯一非用户触发动效)。
- **导航 5 项**:对话 / 项目 / 工作项 / 成员 / 记忆。项目恢复一级(仪表盘不该藏在
  对话页头部链接);设置退为顶栏图标(低频配置);关于保持 `?` 入口;harness 保持深链。

### 3.2 路由

`chat / project / works / members / memory / settings / about / harness`(与现值一致,
无增删);hash 语法、`?project=` 坐标、选中参数(`?work=` `?artifact=` `?member=`)
与首帧不清判据全部照旧,只是地址解析层迁到 `app/router.ts`。

## 4. 交互设计

### 4.1 表态:行动区(取代 v5 流内卡)

- v5 的病:四类卡按锚定时刻长进消息流,随对话滚动漂移,可发现性不稳定。
- 旧收件箱的病:表态与对话上下文割裂。
- **V2 形态:行动区钉在对话页输入区正上方** —— 位置恒定(注意力焦点),仍在
  「聊天框里」(用户裁决的精神),零待办整区消失(简约)。每件待办一行:
  `[状态图标] 一句话摘要 [主按钮]`,点行展开操作表单
  (答问:选项回填/自由文本;验收:附言+接受/要改;收口:同意/先不收;计划:确认开工)。
- 左栏「在等你」分组 + 徽标提供跨项目可见性(不做第六页签 —— 四类表态跟项目内
  对话上下文强绑定,独立 Inbox 会割裂上下文;这是与 Multica 的领域差异)。
- **完结表态仍在流里塌缩成一行事实**(v5 判据保留);`streamCards` 的塌缩逻辑不动,
  只把「未完结卡」的呈现从流内改为行动区。

### 4.2 对话页

- 消息流保持纯净:甲方 ↔「三生」的对话正文 + 内部回合折叠行 + 平台通知计数行。
- 思考/工具折叠块、流式渲染、Esc/■ 停止(只停甲方通道)、断线横幅 + 发送失败撤回
  乐观上屏、busy 拒收当事实显示 —— 判据与测试随迁不改。
- 接待态(零项目)自动进入,视觉上与项目对话同构。

### 4.3 其余域

| 域 | 要点 |
|---|---|
| **工件(一级,一等公民)** | 交付序列:时间倒序一条流;交付物大行(裁决态上屏:待你验收/已接受/要改/未交付);「只看交付物」过滤;点行进抽屉(事实/关系/内容)。2026-11-22:行上「在跑」标记(判据与工作项 DAG 同源 `workRunningState`,读不到给灰点不带字)+ 抽屉 480→680(工件正文是主要读者对象) |
| 项目(一级) | 仪表盘:「现在最要紧的一件事」档位(判据不动)+ 平台记录过滤片 + 成本汇总 |
| 工作项(过程视图,导航退场) | 路由 `#/works` 保留作深链(工件抽屉「产出于」可达);一画布三视图;**页面拆文件**(每文件<300行) |
| 成员(过程视图,导航退场) | 路由 `#/members` 保留作深链;全员并发板 + 回合回放 —— 组织内部视角,给想看过程的时刻 |
| 记忆 | 三段(画像/碎片/语料)分段控件不变 |
| 抽屉 | 三段(事实/关系/内容)与四条纪律不变,升为全局唯一详情面 |
| 剩余批次(更新) | 批次 3=工件序列完整化(版本链 superseded 前后件/质检结论行/验收入口)+ Works 拆文件;批次 4=成员降级+projects/memory/settings 迁移 |

## 5. 视觉体系(深色科技办公)

### 5.1 锚点

**agent 组织的遥测台**:科技感来自密度、秩序、等宽数字,不来自霓虹与装饰。
避免的默认样式:纯黑+单霓虹、SaaS 圆角卡堆、全大写 eyebrow、营销页渐变。

### 5.2 token 四层(自 Multica 采纳,值见 `styles/tokens.css` + `theme.css`)

| 层 | 内容 | 落点 |
|---|---|---|
| Foundations | 表面六阶亮度阶梯(oklch 近纯灰)、文字三级、品牌单强调、语义四件套、字号阶梯(成对 size+line-height)、按钮几何四档、圆角族、间距阶梯、阴影三级 | `tokens.css` |
| Components | nav 行/按钮/输入/卡/状态色/优先级色等语义名,各带 `var(--x, 默认值)` 别名;**组件只消费语义名** | `theme.css` |
| Layout | 页边距、左栏宽(可折叠)、阅读列宽 | `tokens.css` |
| Editor Content | markdown 的 h1-h6/链接/引用/表格/**代码语法色** | `theme.css` |

关键数值纪律(深色):

- 表面六阶:`app-shell 0.155 → page-canvas 0.18 → surface 0.21 → raised 0.235 →
  hover 0.274 → selected 0.30`(oklch L,彩度 0.005-0.007 近纯灰微冷);
- 边框一律白透明发丝线(`oklch(1 0 0 / 6-10%)`),层级不靠阴影;
- 品牌单强调:工程蓝 `oklch(0.68 0.14 255)`(可点/进行中/链接);
- 状态与优先级**映射到语义色**(工作项六状态、review_state、双裁决、优先级),
  不另造色 —— `theme.css` 的 `--status-*` 是唯一映射表,替代 vocab 散落色值;
- 字号阶梯:micro 11/15 · caption 12/16 · label 13/18 · body 14/20 · body-lg 15/22 ·
  title 16/24 · title-lg 18/28 · display 24/32;
- 按钮高四档 24/28/32/36px;列表行高基准 36px;
- **对比度是检查不是口号**:次要文字 ≥4.5:1、装饰 ≥3:1,`tests/web/theme-contrast.test.ts`
  量出来(参照 Multica `theme:check` 进 CI);
- 亮暗双主题结构先搭好(`.dark` + `color-scheme`),V2 只交付深色。

### 5.3 字体(CJK 工程,自 Multica 采纳)

- UI 栈:`system-ui + PingFang SC`(本地服务不打包网络字体);
- **等宽栈故意不列 CJK 字体**:等宽网格只对拉丁字符成立,列 CJK 是虚假的
  对齐承诺(数字/时间/token/id/代码用等宽);
- 数字一律 `font-variant-numeric: tabular-nums`;
- 中文正文行高比拉丁放宽(1.75 vs 1.625)。

### 5.4 不抄清单(领域差异,写死防止漂移)

看板(agent 自动推进,人是观察者)/ shadcn 48 组件全家桶(自建轻量原语,
仅补 kbd·skeleton·tooltip·spinner)/ 主题商店与 CSS 主题系统 / Inbox 一级页 /
多 workspace / 桌面多 tab。

## 6. 架构(低耦合高内聚)

### 6.1 目录(换骨架)

```
web/src/
  app/            App.tsx / AppShell.tsx(frame+页卡+左栏) / router.ts / deepLink.ts
  features/       页面域(高内聚):chat · projects · works · members · memory ·
                  settings · harness · inspector
  entities/       领域判据纯函数(不 import React):artifact/work/project/question/
                  verdict/notice/streamCards/dashboard/orgState/timeline/workGraph/
                  entityMeta/relations
  shared/         ui/(原语+四缺口) · lib/(api/ws/format/markdown)
  stores/         connection.ts / projects.ts / chat.ts(瘦身)
  styles/         tokens.css(层1) / theme.css(层2) / globals.css(语义类,瘦身)
```

### 6.2 依赖单向规则(哨兵钉住)

```
app → features → entities → shared
stores 只被 app/features 消费;entities/stores 不 import features;shared 不 import 上层
```

现存 `stores/chat.ts ↔ lib/data.ts` 循环就此消除:WS 事件只递增 revision 的纪律保留,
revision 住 `stores/projects.ts`;取数 hooks 下放 features(页面私有)或
entities(共享判据)。

### 6.3 store 三域(治 1691 行神经中枢)

| store | 职责 |
|---|---|
| connection | socket 单例、三态(connecting/open/closed)、`applyEvent` 分发 |
| projects | 项目列表、activeProjectId、会话线索引、projectsRevision |
| chat | 当前线消息、inFlight 流式 turns、send/interrupt |

写动作(answer/verdict/confirm/consent)改 feature 内 hooks 直调 `shared/lib/api`。

### 6.4 迁移资产(逻辑不动,只换位置/换皮)

api.ts 契约薄封装 / route.ts+deepLink.ts / 12 件纯函数判据 / DataState·MetadataStrip·
Help(props 不变,按新 token 换皮)/ WS 行为语义(判据与测试随迁)/ 实体脊四纪律。

## 8. 红线(测试钉住的不可协商项)

1. 「读不到 ≠ 没事」:`DataState` 四态,`unavailable` 不许渲染成空/转圈;
2. 对话面无角色名(`chat-no-persona` 哨兵);
3. 表态四状态点各有真实入口与端点对接(行动区或其展开表单);
4. 深链/坐标三纪律(坐标落地切项目、过期清、首帧不清);
5. interrupt `channel:"client"` 只停甲方通道;
6. 断线时发送/中断如实说「没发出去」,乐观上屏撤回;
7. 依赖方向哨兵(§6.2)与对比度哨兵(§5.2)常绿。

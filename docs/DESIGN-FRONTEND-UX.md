## 1. 设计原则(六条,Apple 式的操作化)

1. **一屏一件事**:每个页面只回答一个主问题;其余全部收进折叠行或别的页。
2. **默认安静**:默认视场里只出现「有信息量」的元素。零、空闲、常态**不出现**
   (而不是出现并说「0」)。诚实纪律不变:读不到 ≠ 空 —— 读不到给一行可点的小字,
   不铺横幅、不吓人。
3. **渐进披露**:任何详情一次点击可达,但默认折叠(成本、文件系统、内部协作、原始字段)。
4. **一条主路径**:每个上下文只有一个主按钮;次动作进详情或「…」。
5. **删胜于收**:两处说同一件事 = 删掉一处,不是把两处都排版好看。
6. **形是信号,句子不是**:文本总量棘轮继续只减不增,且**目标值下调**(现 9,270 字 →
   本版目标 ≤ 7,500,分两批);徽标与 pill 非零才出现。

## 8. 不做什么(在 v2 基础上追加)

- 不删任何诚实判据:四态、读不到 ≠ 空、平台通知不回对话页 —— 它们是「不撒谎」,
  不是臃肿;臃肿是「重复与常驻」,两回事;
- 不删「最要紧的一件事」「待你验收」「待答」这三个甲方必经面;
- 不做每页塞一个 AI 摘要式的「聪明」(那是另一种臃肿);
- 导航恒 6 页签 + `?` 不变。

## 9. 与哨兵/预算的关系(汇总)

- 删段落 = 判据迁移或变更,**逐一记录**(§4 表中已点名四个哨兵文件);
- 文本预算总量棘轮:9,270 → ≤ 7,500(两批),每文件基线随删减重算,只许减;
- 新增组件(项目此刻行、视图切换、平台记录过滤器)各自带哨兵 + 变异自检,
  沿用 EntityInspector 三纪律与「仪器也要有变异」。
